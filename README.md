# 请求与缓存检查器

独立 TauriTavern 本地诊断扩展。参考 ST-Cache-Optimizer 的观察目标，独立实现，不重排、不修改提示词，不额外调用模型。

安装地址：https://github.com/18084213166/ST-Request-Inspector

在手机扩展管理中通过 Git 地址安装，重启客户端。魔法棒扩展菜单内点击“请求 / 缓存检查”。先产生至少两次请求，再选择同一聊天的对比记录。

功能：记录实际通过前端 chat-completions/generate fetch 发出的 JSON；比较同一聊天的请求，显示第一处差异、变化消息、完整请求和回复。自动关联并发请求与各自响应。可手选基准、导出单条、清空全部。

缓存 Token 以响应原始 usageMetadata 或 OpenAI usage 为准；未提供显示未知，不假定为零。字符前缀相同比例不是 Token 命中率，也不能证明变化是缓存未命中的唯一原因。模型、服务端转换、缓存有效期、阈值、路由等也会影响命中。本插件看到宿主前端发出的请求，无法看到 Tauri 原生层或中转服务端后续转换，也无法可靠反推每段文字来源于哪个世界书条目。

本机 IndexedDB 保存最近 20 条、约 600 万字符。单请求超过 150 万字符不存全文；响应捕获上限 800 万字节，超过会明确标记。记录包含私密提示词和回复，导出文件请自行保管；扩展移除不一定删除数据库，可先在面板清空。已知密钥、认证头、凭证及配置原文不保存；用户直接写进消息正文的秘密无法自动识别。

支持原生 Google 和个人中转普通/抗截断流式；其它使用同一 fetch 通道的后台插件请求也会记录，不保证每条都是聊天回复。非 fetch 的宿主请求通道无法捕获。旧消息不追溯。可与个人 PayGo 费用插件并用。

测试覆盖差异、密钥字段过滤、缓存未知与零的区别及两种 usage 格式；尚未在实际手机上验证界面。若看不到记录，请确认客户端使用支持前端 fetch 的扩展接口。
